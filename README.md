# CubeVision — カメラでルービックキューブの回転を追跡するアプリ

カメラ1つで、手持ちの普通の 3x3 ルービックキューブを映すと、**回した手順をリアルタイムに読み取り、画面の3Dキューブで同じ動きを再現**します。
スマートキューブ（Bluetooth 内蔵キューブ）がなくても、手順ログ・TPS・自動計測タイマー・3Dリプレイが使えます。

ブラウザだけで動く PWA です（インストール不要・処理はすべて端末内・映像は外部に送信しません）。

## できること

| 機能 | 内容 |
|---|---|
| 6面スキャン | 指示に従って1面ずつカメラに見せると、色と配置を自動で取り込み。完成でも崩れた状態でもOK。読み間違いは展開図をタップして修正、面の向きの間違いは自動補正 |
| リアルタイム追跡 | 回した手を検出して 3D キューブ（cubing.js）に反映。キューブの持ち方（向き）にも追従。見えない面の回転は、後で影響が見えた時点で遡って推定 |
| 手順ログ | 持ち方基準（R U R' U' …）／センター色基準を切替。未確定の手・推定した手を区別して表示 |
| 解法ガイド | 今の状態から揃えるまでの手順を表示し、回すと自動で進む |
| タイマー | WCA スクランブルを生成し、今の状態から崩す手順を案内 → 崩し終わると自動でインスペクション → 最初の1手で開始 → 揃った瞬間に停止（スマートキューブと同じ流れ） |
| 分析・履歴 | 手数・TPS・クロス/F2L/OLL/PLL の区間、ベスト・ao5・ao12。3D リプレイ、JSON/CSV 書き出し |
| デモ | カメラがなくても、合成カメラ（three.js で描いたキューブの映像）で全機能を試せる |

## 使い方

```bash
npm install
npm run dev        # http://localhost:5173 を開く
```

スマホで使うときは同じ LAN で `npm run dev:lan` を実行し、表示された `https://<PCのIP>:5173/` をスマホで開きます
（カメラは HTTPS が必須なので自己署名証明書を使います。最初に出る警告は承認してください）。

1. **カメラを置く** — キューブより少し上から、キューブの「カメラ側の面」と「上面」の **2面が映る** ようにすると精度が大きく上がります。
2. **6面スキャン** — 画面の指示どおり（標準配色なら「緑の面を正面・白を上」など）に面を見せます。少し止めると自動で取り込みます。
3. **回す** — 3D キューブと手順ログに反映されます。最初は1手ずつ軽く止めるくらいから。
4. **タイマー** — 「タイマー」タブでスクランブルを出して計測。

詳しくはアプリ内の「使い方」を参照してください。

## しくみ

```
カメラ ──requestVideoFrameCallback──▶ 認識 Worker（OpenCV.js）
                                      ├ ステッカーらしい四角形を検出（輝度 + a*/b* のエッジ）
                                      ├ 形と間隔が揃う四角形を 3x3 格子に当てはめ（射影変換）  ← 最大3面
                                      ├ 面をカメラフレーム（正面/上/右…）と向きに割り当て
                                      ├ 各セル中央部の色を CIELab でサンプリング（手の部分は MediaPipe で除外）
                                      └ 追跡エンジン
                                          ├ 観測器: 数フレーム安定した読みだけを「観測」にする
                                          └ デコーダ: 仮説 =（キューブ状態, 24通りの姿勢）のビームサーチ
                                             各観測で 0〜2 手＋持ち替えを展開し、予測される見え方と照合
メイン（Preact）◀── 手順・状態・姿勢 ──┘   → 3D 表示（cubing.js TwistyPlayer）・タイマー・履歴
```

ポイントは **映像から手順を直接組み立てない** ことです。内部に持っているキューブ状態に候補の手を適用し、
「そうだとしたらカメラにはどう見えるか」を全候補で照合して、最も矛盾の少ない手順を選びます。
色の読み間違いや指で隠れたステッカーがあっても、他のステッカーとの整合性で正しい手が選ばれ、
カメラから見えない面の回転も、その影響が見える面に現れた時点で遡って推定されます。

色の判定は汎用の色分類ではなく、**スキャン時にそのキューブ・その照明で6色を実測**して使います（各色9枚ずつになるよう
ハンガリアン法で割り当て）。パステルなど変わった配色にも対応し、追跡中も確信の持てる観測で代表色をゆっくり補正します。

## 既製品の調査と採用したもの

「既存のものをできる限り使う」方針で GitHub を調査しました。

| プロジェクト | 内容 | このアプリでの扱い |
|---|---|---|
| [cubing.js](https://github.com/cubing/cubing.js)（MPL-2.0/GPL-3.0） | 3D キューブ表示・記法・状態計算・ソルバー・WCA スクランブル | **そのまま採用**（3D表示・解法・スクランブル・状態の検証） |
| [OpenCV.js](https://docs.opencv.org/)（`@techstark/opencv-js`, Apache-2.0） | 画像処理 | **採用**（エッジ・輪郭・四角形検出） |
| [MediaPipe Hand Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker)（Apache-2.0） | 手の 21 点検出 | **採用**（指で隠れたステッカーを読まない） |
| [AllefDouglasDev/rubik-cube](https://github.com/AllefDouglasDev/rubik-cube)（MIT） | ブラウザのキューブトレーナー。カメラで正面1面を見て手順を復号する実験機能 | **設計を参考**: ビームサーチ復号・ハンガリアン法の色割り当て・格子への吸着。これを「最大3面」「24姿勢を仮説に含める（持ち替え対応）」「ソフトな色コスト」「見失い検出と復帰」「ステッカーレス対策」に拡張 |
| [kkoomen/qbr](https://github.com/kkoomen/qbr), [RubikVision](https://github.com/Charles-AM/RubikVison), [cube-cv](https://github.com/HANS-2002/cube-cv), [RubikClear](https://github.com/steelburn/RubikClear) | カメラで面を読むソルバー・タイマー（静止スキャン） | 手法を参考（輪郭検出・Lab/CIEDE2000・多フレーム投票）。いずれも手順の追跡はしない |
| [MigicCube](https://github.com/idootop/MigicCube) | YOLO で位置検出 + OpenCV で色読み（Python） | 参考のみ（ブラウザで重いモデルを動かすより、軽量な古典 CV で十分な精度が出たため） |

調査の結論として、**「面の色を読む」既製品は多数あるが、「回転を1手ずつリアルタイムに追跡する」既製品は実用レベルのものが見当たらない**
（上記 rubik-cube の実験機能が最も近い）ため、追跡部分はそれらを土台に作り込んでいます。

## 精度の確認

カメラなしで同じ処理経路を検証できるようにしてあります。

- `npm test` — 状態モデル（CLAUDE.md の必須テスト）、cubing.js との整合、ソルバー、復号器のシミュレーション、
  OpenCV.js による合成画像からの面検出（ランダムな 40 姿勢）、合成フレーム → 追跡の通し試験、6面スキャン、区間分割
- `npm run build && npm run e2e` — ビルド済みアプリをヘッドレス Chromium で開き、デモモード（three.js の合成カメラ、
  回転中は指が一部を隠す）で「6面スキャン → 30 手」を実行して、追跡結果を正解と比較。`E2E_MODE=timer` でタイマーの流れ

開発中の計測値（合成データ。実カメラでの値ではありません）:

| 条件 | 結果 |
|---|---|
| 復号器シミュレーション（誤読3%・隠れ10%・1〜2手/観測） | 2面見え: 97〜100% / 1面のみ: 84〜99% |
| 合成画像の面検出（ランダム姿勢 40） | 全セル正しく読めた 36/40、2面以上検出 40/40 |
| E2E（ヘッドレス Chromium・約13fps・2面見え・2TPS・30手×3回） | 30/30 手正解・最終状態一致 3/3 |
| ステッカーレス（溝が見える）で完成まで | 3回中2回完全一致（完成も検出） |

## 制約

- 速く回すほど取りこぼしやすくなります（多くのカメラは 30fps）。目安は 1 秒 2〜4 手。取りこぼしは後続の観測で
  補正されますが、どうしても説明できなくなると「見失い」を表示します（ごまかして誤った手順を記録しないため）。
- 1面しか見えない置き方では、カメラの反対側の面の回転は後から推定になります。2面見える置き方を推奨します。
- 溝がほとんど見えないステッカーレスキューブで、同じ色が大きくつながった状態（完成間際など）は検出が不安定になることがあります。
- 中層（M/E/S）回しは、センター基準のため両側の面を回したのと同じ手として記録されます。
- 3x3 専用です。

## 構成

```
src/cube/        キューブの状態モデル（3D座標モデル）、cubing.js との変換、ソルバー（専用 Worker）、区間分割
src/vision/      カメラ、認識 Worker、四角形検出（OpenCV.js）、格子当てはめ、面の配置、色、手の検出（MediaPipe）
src/track/       追跡エンジン（観測器・色モデル・ビームサーチ復号器）— カメラも DOM も知らない
src/scan/        6面スキャン（取り込み・色割り当て・自動補正）
src/app/         アプリの状態（コントローラ・タイマー・設定・保存）
src/ui/          画面（Preact）
src/synthetic/   合成カメラ（three.js）とデモの台本
tests/           Vitest（tests/render.ts はテスト用のソフトウェアレンダラ）
scripts/e2e.mjs  ヘッドレス Chromium による E2E
```
